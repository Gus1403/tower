# subswitch vs Tower: account capacity

subswitch is the owner's earlier private tool (a macOS/Linux daemon for multiple Claude and Codex subscriptions). We read it for ideas only and copied no code. Its README describes it as "a local coordination layer … when a limit is reached, chooses the account with available headroom so new work can continue through the official clients without pooling credentials or proxying traffic." Tower takes the same stance, but it works only on agents that Tower launched itself over ACP.

| Feature | subswitch | Tower before | Tower after Wave C | Notes |
|---|---|---|---|---|
| Discover one config home per account (`~/.claude-N`, `~/.codex-N`) | Yes (configured homes, `make-codex-homes.sh` builds thin Codex homes) | Yes (`accounts.ts` scans `~` for `.claude*` / `.codex*` that have a credential *file*, contents never read) | Same | Tower never creates or links homes. |
| Login status per account | Yes, plus auth-dead latches on 401/`invalid_grant`/empty credential and a token keepalive refresh | Yes (`claude auth status`, `codex login status`, `devin auth status`) | Adds `status: 'logged_out'` when `loggedIn === false`, so Automatic and rotation skip it | No keepalive and no token refresh: Tower never touches tokens. |
| Usage tracking (5-hour / weekly %, Fable-scoped headroom) | Yes (API probes with backoff, cached usage, CodexBar display, Fable headroom ranking) | `usedPct` field exists; mostly unmeasured | Unchanged | Tower does not call usage APIs. Picking uses `usedPct` only when it is known (unknown counts as 50). |
| Exhaustion detection (limit banner) | Strict banner: `You've hit/reached your … limit` (straight or curly apostrophe), Claude tree prefixes, the last 40 lines only; 429, `rate limit`, network, transport and timeout lines never count | Loose `LIMIT_RE` (`usage limit`, `429`, `quota`, …) sets `limitHit` → UI offers "Continue on another account" | `limitHit` stays loose (manual hint). **Rotation** is triggered only by the strict banner idea (`isLimitBanner` in `rotation.ts`: `You've hit/reached your … limit` or Codex `usage_limit_reached`, with any line that mentions 429/rate limit/network/timeout excluded), read from the error text plus the last 20 stderr lines | Same precedence as subswitch: an HTTP 429 alone never marks an account exhausted. |
| Reset-time parsing | `H:MM`, `HH:MM`, `h:MMam/pm`, timezone in parens (unknown tz → `resetAt=null`), dates, `tomorrow`, relative durations, plausibility caps per wall kind (5 h session, 7 d usage/Fable) | None | `parseResetAt`: ISO timestamps; `try again in 2h 13m` / `in 4 days 23 hours 35 minutes`; `resets 13:41`, `resets at 5pm`, `resets 9:20pm (Europe/Berlin)`, `resets 13:41 on Oct 30`, `try again at 3:41 PM`. A bare clock means its next occurrence; a past month/day rolls to next year. Nothing parseable → now + 1 h | Simpler than subswitch: **the timezone in parentheses is ignored and the server's local clock is used**, there are no per-kind plausibility caps, and `tomorrow`/weekday words are not parsed. |
| Exhausted state + auto-clear at reset | Walled latch per home; clearing it needs a fresh capture or an operator clear, with tombstones against resurrection | None | `status: 'exhausted'` + `resetAt`, persisted. Clears automatically at `resetAt` (timer, and also checked on every `list()`/refresh); activity `cleared` | Tower trusts the parsed clock. It has no second-capture proof and no tombstones. |
| Excluded homes | Yes (excluded/walled/unsafe homes rejected by `codex-home --check`) | None | `POST /api/accounts/:id/exclude {excluded}` → `status: 'excluded'`, persisted; skipped by Automatic and auto-rotate; activity `excluded` / `included` | |
| Operator clear | `operator-clear` tombstone | None | `POST /api/accounts/:id/clear` → ok; activity `cleared` | |
| Pick the account with headroom | Lowest score after hysteresis and cooldown; a hard limit bypasses cooldown; when every account is red it rides the one with the most raw headroom, deduplicating notifications | `pick`: logged in, lowest `usedPct`, then fewest running | `envFor('auto')` and rotation choose among `status === 'ok'` accounts of the same kind: logged in first, then lowest `usedPct`, fewest running, then id. If no account is ok, launch keeps the old behaviour | No hysteresis, cooldown or ladder: Tower only acts on a limit hit or on a new launch. |
| Continue after a limit | Controller-owned resume of the *same* Claude/Codex pane on the new home (`subswitchctl resume`), post-reset nudges, Codex shim relaunches once with the new home | Manual `POST /api/agents/:id/move` (new agent with the conversation summary in its task; the old one is archived) | Auto-rotate (default on, `POST /api/rotation {autoRotate}`): on a banner, the account is marked exhausted and `manager.move()` runs to the best ok account. The new agent gets `movedFrom {agentId, accountId}`. Activity `moved`, or `no_account` ("All Devin accounts are at their limit; next resets 13:41") | Tower starts a **new** ACP session with a text summary of the conversation. It does not transfer the native session, so model context is lost beyond that summary. |
| Loop guards | Dedup by banner identity, cooldowns, ladder, `unlanded_switch_attempts` | — | A move chain stops after 3 hops (counted through `movedFrom`). An agent that is stopped, archived or observed through tmux is never moved. Only one rotation runs per agent at a time | |
| Activity / incident log | Incident ledger with open/resolve, alerts, `shim.log`, stale-banner sightings | — | `RotationState.activity`: newest first, at most 200 entries, persisted, each entry one human line; WS `rotation` | No alerting or incident lifecycle. |
| Counters | `operationalCounters` (e.g. `shim_stale_home_redirected`, `claude_wall_stale_banners`) | — | None (the activity log only) | |
| Persistence | State files under `~/.config/subswitch`, merged under a lock | Agents/notes JSON | `<TOWER_DATA_DIR or ~/.local/state/tower>/rotation.json`, mode 600, tmp + rename | Single process, so no merge or locking. |
| Scope of control | Rewrites the account pointer for *every* client on the host (Codex shim, Claude panes in tmux/cmux, CodexBar) | Its own agents only | Its own agents only | Tower **does not** proxy traffic, pool credentials, switch the global CLI pointer, or touch sessions of other tools or tmux panes it observes. |
| Cross-host (Mac ↔ Forge) | Separate lineages, reconnect contracts | — | — | Out of scope. |
